## Proposed next steps

1. Block deployment until findings 1–6 are resolved.
2. Define graded evidence states: complete, meaningful-partial, tool-start failure, and still-writing. Reject only the last two from provider delivery; do not equate every missing field with an empty dump.
3. Parse baseline attempts independently and accept a successful complete attempt despite earlier failed attempts. Persist retry usage per UTC date and retain the exact filename being checked.
4. Give pending items an immutable wall-clock deadline and durable states for provider-send and operator-warning attempts. Retry transient failures; distinguish duplicate/limit refusal from storage or lock failure.
5. Decide explicitly between at-most-once and at-least-once warning semantics—`mail()` plus a local JSON row cannot guarantee exactly-once delivery.
6. Add adversarial tests for localized ping, no-route output, one good/one failed mtr, all-`???`, recovery-only, incomplete-start/full-recovery, incremental file snapshots, restart after each state transition, midnight crossing, and two concurrent monitor processes.
7. Make logs state only the verified predicate, such as “gate failed: reason,” and bind reservation release to the original reservation date.
