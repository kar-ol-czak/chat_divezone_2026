Verdict: **do not approve unchanged.** The core “nothing can freeze the probe” invariant is not met.

1. **CRITICAL — startup DNS can hang indefinitely.** The probe explicitly acknowledges that `getaddrinfo()` lacks a timeout, then calls it synchronously before initializing the cycle loop ([probe.py:140](/Users/karol/Documents/3_DIVEZONE/Aplikacje/Chat_dla_klientow_2026/_diag_local/railway_reverse_probe/probe.py:140), [probe.py:142](/Users/karol/Documents/3_DIVEZONE/Aplikacje/Chat_dla_klientow_2026/_diag_local/railway_reverse_probe/probe.py:142), [probe.py:149](/Users/karol/Documents/3_DIVEZONE/Aplikacje/Chat_dla_klientow_2026/_diag_local/railway_reverse_probe/probe.py:149)). A stalled resolver produces exactly the dangerous state: process alive, START lines printed, then silence. Setting `_STOP` on SIGTERM does not forcibly terminate an in-progress resolver call.

2. **HIGH — the per-metric timeout is not a hard wall-clock deadline.** Both metrics use `socket.create_connection()` ([probe.py:87](/Users/karol/Documents/3_DIVEZONE/Aplikacje/Chat_dla_klientow_2026/_diag_local/railway_reverse_probe/probe.py:87), [probe.py:106](/Users/karol/Documents/3_DIVEZONE/Aplikacje/Chat_dla_klientow_2026/_diag_local/railway_reverse_probe/probe.py:106)); CPython performs `getaddrinfo()` before applying the socket’s connect timeout. Numeric IPs normally resolve locally on Linux, but that is not a process-enforced deadline. For TLS, `left` is calculated before `ssl.create_default_context()`, whose CA-loading work is unbounded and is not deducted from the handshake timeout ([probe.py:107](/Users/karol/Documents/3_DIVEZONE/Aplikacje/Chat_dla_klientow_2026/_diag_local/railway_reverse_probe/probe.py:107), [probe.py:110](/Users/karol/Documents/3_DIVEZONE/Aplikacje/Chat_dla_klientow_2026/_diag_local/railway_reverse_probe/probe.py:110), [probe.py:111](/Users/karol/Documents/3_DIVEZONE/Aplikacje/Chat_dla_klientow_2026/_diag_local/railway_reverse_probe/probe.py:111)). The handshake itself receives a socket timeout, but the claimed total TLS budget is false.

3. **HIGH — stdout is another unbounded blocking path.** Every sample performs a synchronous flushed write ([probe.py:166](/Users/karol/Documents/3_DIVEZONE/Aplikacje/Chat_dla_klientow_2026/_diag_local/railway_reverse_probe/probe.py:166), [probe.py:174](/Users/karol/Documents/3_DIVEZONE/Aplikacje/Chat_dla_klientow_2026/_diag_local/railway_reverse_probe/probe.py:174)). If Railway’s log pipe stops draining, the sole thread can block indefinitely. There is no independent watchdog or killable worker, so absence of output is still the only symptom of several live-process hangs.

4. **HIGH — this is not a one-way “return-direction” measurement.** The description claims it measures exactly Railway→server ([probe.py:4](/Users/karol/Documents/3_DIVEZONE/Aplikacje/Chat_dla_klientow_2026/_diag_local/railway_reverse_probe/probe.py:4), [probe.py:8](/Users/karol/Documents/3_DIVEZONE/Aplikacje/Chat_dla_klientow_2026/_diag_local/railway_reverse_probe/probe.py:8)), but TCP connect timing covers a bidirectional three-way handshake ([probe.py:82](/Users/karol/Documents/3_DIVEZONE/Aplikacje/Chat_dla_klientow_2026/_diag_local/railway_reverse_probe/probe.py:82), [probe.py:87](/Users/karol/Documents/3_DIVEZONE/Aplikacje/Chat_dla_klientow_2026/_diag_local/railway_reverse_probe/probe.py:87)). It is a useful **reverse-initiated RTT/reachability** measurement, but cannot isolate which leg lost packets.

5. **HIGH — the Railway source may not represent the PG proxy’s return path.** The code records only destination addresses ([probe.py:47](/Users/karol/Documents/3_DIVEZONE/Aplikacje/Chat_dla_klientow_2026/_diag_local/railway_reverse_probe/probe.py:47), [probe.py:51](/Users/karol/Documents/3_DIVEZONE/Aplikacje/Chat_dla_klientow_2026/_diag_local/railway_reverse_probe/probe.py:51)); START output contains no region, replica, public egress IP, ASN or deployment identity ([probe.py:136](/Users/karol/Documents/3_DIVEZONE/Aplikacje/Chat_dla_klientow_2026/_diag_local/railway_reverse_probe/probe.py:136)). A throwaway Railway compute service may use a different region, egress prefix and route from the public PostgreSQL proxy. Without proving source equivalence, the experiment does not fully answer the provider’s objection.

6. **HIGH — metrics grouped on one line are not simultaneous.** One timestamp is captured before four sequential probes, each potentially lasting five seconds ([probe.py:153](/Users/karol/Documents/3_DIVEZONE/Aplikacje/Chat_dla_klientow_2026/_diag_local/railway_reverse_probe/probe.py:153), [probe.py:155](/Users/karol/Documents/3_DIVEZONE/Aplikacje/Chat_dla_klientow_2026/_diag_local/railway_reverse_probe/probe.py:155), [probe.py:158](/Users/karol/Documents/3_DIVEZONE/Aplikacje/Chat_dla_klientow_2026/_diag_local/railway_reverse_probe/probe.py:158)). Therefore “target and control failed in the same line/minute” does not prove concurrent failure, despite the intended minute-by-minute comparison ([probe.py:29](/Users/karol/Documents/3_DIVEZONE/Aplikacje/Chat_dla_klientow_2026/_diag_local/railway_reverse_probe/probe.py:29)).

Proposed next steps:

1. Treat the review as blocking until startup DNS and every metric have a genuinely enforceable outer wall-clock deadline; add an independent freshness watchdog capable of killing a live-but-silent process.
2. Verify configured Railway SIGTERM grace, then test SIGTERM during DNS, TCP connect, stalled TLS handshake, stdout blockage and sleep.
3. Run fault injection for black-holed TCP, accepted-but-silent TLS, bad certificate, refused control port, DNS stall and interval overrun. Assert bounded elapsed time and explicit output.
4. Run at least 10,000 accelerated cycles while sampling `/proc/$pid/fd` and RSS.
5. Establish experiment validity before collecting evidence: record Railway region, deployment ID, image digest, Python/OpenSSL versions and public egress IP; prove whether that egress represents the PG proxy’s return path.
6. Baseline both destination ports and the control from Railway, confirm firewall policy, and independently verify the control IP/ASN/service throughout the test.
7. Define the result as “reverse-initiated TCP reachability/RTT,” not one-way routing proof. Record per-metric timestamps or offsets so target/control failures are not treated as simultaneous without evidence.
8. Validate log retention and export, detect counter resets/redeploys and clock steps, and define a completeness rule for missing 30-second samples.
